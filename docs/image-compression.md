# 全站展示图片压缩

2026-11-06 在 `perf/public-api-loading` 分支处理。只新增展示衍生文件，不改生产数据库，不覆盖原图、冻结素材、裁剪或人物内容。

## 覆盖和结果

扫描 public 全部栅格图片、历史内容归档，以及公开赛季名单中的 gallery、match、avatar、mobile、detail 地址。2,358 个 URL 引用去重后对应 1,839 份源图；生成 1,838 个内容寻址 WebP 文件。另有 3 个 SVG 保持矢量形式。动画如存在则保留原版。

较小的原文件继续使用。WebP 有损压缩不能表述为完全无画质损失；已在相同展示尺寸下抽查丽芙、昔涟、菲欧妮的头像、对局与图鉴对比，未发现明显构图变化或新增白边。全量编码检查透明通道不丢失。

## 加载与版本保护

- `DisplayImage` 只替换已知源版本的显示地址。新上传且尚未处理的版本继续加载其原地址。
- 优化图不可用时回退到同一源版本；原版也不存在时，保留原有占位逻辑，不借用其他角色或历史版本。
- 详情页放大链接和素材编辑器使用原图，便于高清查看和准确编辑。
- `/image-variants/<内容哈希>.webp` 由静态资源服务提供，设置一年 immutable 缓存，不经过 `/api/media` 的 R2 读取路径。
- 版本索引使用哈希缩短映射，不将全部长素材 URL 放入前端包。索引约 86 KB 未压缩；构建体积仍须纳入首屏性能评估。
- 未修改已冻结的历史数据库记录，也未替换任何历史文件字节。原有历史哈希验证仍在每次构建执行。

## 重建

运行 `NODE_USE_ENV_PROXY=1 npm run images:compress`。脚本只读公开接口，优先复用本机准备目录中的同哈希源文件；缺少时下载精确版本。生成文件放 `public/image-variants`，索引放 `src/data/image-variants.json`，逐文件报告放 `.local/image-compression/report.json`。

脚本验证版本哈希、只接受体积更小的输出，并保留既有衍生文件以兼容旧客户端。应将生成文件与索引作为同一次发布交付。上线前执行 check、test、test:e2e、build；发布后核验图片命中、原版回退和国内真实下载耗时。
