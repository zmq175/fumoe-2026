# 首屏与公开接口优化

目标是首页和对局中心在目标网络下 1 秒内显示可用内容；尚未达成或验证国内网络 1 秒指标，不能用本地测试通过代替性能验收。

## 已定位的等待

2026-11-06 对线上公开接口只读采样（代理出口 LAX，非国内运营商测速），服务端约几十至一百多毫秒，客户端仍有数百毫秒乃至 1 秒的网络等待。继续减少关键链路请求串行关系和资源体积更有意义，SQL 查询本身不是唯一瓶颈。

## 改动

- HTML 在主脚本下载期间启动总览请求，仅首页与 `/matches`，主应用消费同一 Promise，不重复请求。失败后正常重试；后续轮询重新读接口，未保存旧比分。
- 后台裁图工具、赛季配置按需加载，关联 CSS 也随组件加载。赛制校验 schema 与纯展示计算拆分，避免 Zod 校验库进入访客首屏；服务端和后台校验规则保持原样。
- 首页总览的生命周期检查与五项读取合为一个 D1 batch。边界到期时推进赛季并重新读取，保持日切换行为。
- 总览、积分、轮次及赛季列表/详情复用条件校验。每次仍检查最新数据；未变返回 304，变化返回完整响应。鉴权和写接口未加入缓存。
- 对局中心前两张卡的图片使用 eager/high priority，其他继续懒加载；不改变素材与卡片比例。
- Vite 内容哈希 JS/CSS 设置一年 immutable 缓存；更新通过新文件名生效，HTML 不长期缓存。

## 验证和限制

浏览器测试阻塞主脚本，确认总览请求已提前发出且主应用不重复请求；阻塞全量比赛、名单和积分接口，确认首页与对局中心仍能先显示总览中的实时对局。后台组件加载、配置流程、历史页面、图片回退、投票继续运行完整回归。

1 秒验收需要在国内实际网络分别测冷启动与再次访问、桌面与手机，记录导航到首排图片可见和投票按钮可用的时间，以及 P50/P95。当前无法据代理环境保证国内 P95 < 1s；首次文档请求本身超过 1 秒时，应用层优化无法补回这段等待。

本轮尚未合并或部署，不能称线上首屏已提速。未做数据库迁移，未改变历史记录。

## 前端请求并发

- 首次访问：总览与 JS 下载并行，赛季列表、登录状态独立请求；需要准确赛季身份的数据在总览确认后并发请求。
- 后续轮询：已知赛季的比赛、轮次、积分（以及到刷新周期的名单）与总览同时发起。响应必须在总览确认同一赛季 ID 和 slug 后才应用；赛季切换时丢弃旧响应，重新并发读取新赛季。
- 相同 URL 的公开 GET 在同时进行时合并为一个请求，成功或失败结束后移除，不额外缓存比分。不同赛季、鉴权请求、写请求及自带请求选项的调用不合并。
- 继续保留页面隐藏暂停轮询、15 秒周期不重叠及各区域独立更新。串行登录→拿到身份→查询个人选票，以及投票提交后的确认流程不能随意并发。

浏览器测试通过阻塞总览验证并发已经发生，并覆盖赛季切换防串数据。并发改善后续轮询等待，不等于取消首次确认赛季的依赖。

最终验证：`npm run check`、148 项单元/集成测试、36 项浏览器测试和构建通过；本轮服务器改动后七轮隔离赛季模拟通过。后续增量仅为前端并发与请求合并，无赛制变动。尚未部署，暂无真实国内网络 1 秒达标证据。
