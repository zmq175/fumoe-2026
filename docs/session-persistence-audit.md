# Chrome 登录状态丢失排查

用户反馈隔天需要重新输入邮箱验证码，无法取得反馈设备的请求记录。

## 已验证

- 登录接口签发的 Cookie Max-Age 为 2592000 秒，JWT 期限为 30 天。
- 真实路由与隔离 SQLite 测试：同一 Cookie 在第 1、2、29 天有效，第 31 天失效。
- 请求失败不会主动清除前端已有登录展示。
- 目前未复现反馈设备的退出原因，不把缺少缓存控制认定为根因。

## 本次防护与诊断

- 登录接口及个人选票响应设为 `private, no-store`；前端读取 `/api/auth/me` 也使用 `cache: no-store`。
- `/api/auth/me` 无有效会话时写入结构化事件 `session_unavailable`，原因分为 `missing`、`expired`、`invalid`、`account_unavailable`。
- 日志不含邮箱、Cookie、JWT、IP 或完整 User-Agent，不输出用户标识。
- `missing` 也包括正常未登录访客，不能仅凭这个计数认定 Cookie 被浏览器清理。诊断只能提供服务端类别，无法重建浏览器清理过程。
- 未延长登录期限、自动续签或修改生产账号数据。发布前尚不能从生产日志观察这些新事件。

## 观测方法

在 Worker 日志中筛选 `session_unavailable`，比较各原因发生情况。`invalid` 需结合密钥变更记录核查；`expired` 表示凭证确已过期；`account_unavailable` 需核查账号状态。不要通过放行失效凭证恢复登录。

## 后续排查：登录恢复请求与用户操作的竞态

- 图片压缩版本已从 main 发布，登录诊断保持启用。
- 使用现有 Cloudflare OAuth 凭据查询最近 24 小时 Observability 历史日志返回 HTTP 403；账户列表可读取，日志查询权限不足。没有读取或输出凭据。
- 本轮 55 秒实时日志观察窗口没有捕获 `session_unavailable`，不能据此排除偶发问题。
- 新增浏览器复现：延迟首页 `/api/auth/me` 的匿名响应，期间完成验证码登录，再释放旧响应。旧代码会清除刚建立的页面登录状态及本地展示缓存；回归测试明确失败。这并不证明浏览器 Cookie 丢失，也不能直接归因为用户反馈的隔天退出。
- 修复：登录／退出动作递增会话操作版本；初始化检查只能应用同版本且组件仍有效的结果。旧响应不能覆盖更新后的认证操作。真实认证仍由服务端决定。
- 回归覆盖迟到的匿名响应覆盖登录，以及迟到的已登录响应覆盖主动退出两种方向。
- 根因范围：确认并修复前端可复现的竞态；实际用户跨天会话丢失尚需历史日志权限或后续有效诊断事件。

本次验证：153 项单元／集成测试、42 项浏览器测试、类型检查及构建通过。现有 Wrangler OAuth 授权不含 `workers_observability_telemetry:write`；查询历史日志需要相应授权（Cloudflare API 权限名 Workers Observability Write），并非部署或实时 tail 权限。
